First, think like a detective

A database table is like a classroom register. Every row is one student. Every column is one detail, like name, roll number, or marks. In database testing, you often do not just ask “what data is inside?” You also ask “is this table built correctly?” That is where these queries come in.

Table = sheet Row = one record Column = one field Null = empty Key = special column

Core words in simple language

SELECTMeans “show me data.”
FROMMeans “from this table.”
WHEREMeans “only show matching rows.”
INFORMATION_SCHEMAIs the database’s notebook that stores table details.
COLUMNSThis notebook page keeps column information.

Query stories, not boring definitions

Each query is like asking the database a tiny question. The answer helps you check whether the design is correct. `INFORMATION_SCHEMA.COLUMNS` is the MySQL metadata table for column details, and `IS_NULLABLE` / `COLUMN_KEY` tell you if a column can be empty or if it is a key [web:19][page:1].

Query Fun meaning What tester learns
SHOW TABLES; The database says, “Here are my rooms.” Check whether your expected table exists.
SELECT COUNT(*) FROM information_schema.columns WHERE table_name = 'customers'; Count the number of building blocks in the table. Verify total columns.
SELECT column_name FROM information_schema.columns WHERE table_name = 'customers'; Ask for the table’s column name list. Confirm names match design.
SELECT column_name, data_type FROM information_schema.columns WHERE table_name = 'customers'; Ask, “What is this column made of?” Check type like int, varchar, date.
SELECT column_name, is_nullable FROM information_schema.columns WHERE table_name = 'customers'; Ask, “Can this field be empty?” Verify NULL / NOT NULL rules.
SELECT column_name, column_key FROM information_schema.columns WHERE table_name = 'customers'; Ask, “Is this column a hero key?” Check PRI, UNI, or MUL.

Easy memory tricks

Table found?Use SHOW TABLES.
Column count?Use COUNT(*) on information_schema.columns.
Column names?Use column_name.
Data type?Use data_type.
Empty allowed?Use is_nullable.
Key check?Use column_key.

Why these fields matter

In MySQL, `IS_NULLABLE` tells you whether the column can store `NULL` or not, and `COLUMN_KEY` tells you whether the column is `PRI`, `UNI`, or `MUL` [web:19]. This helps testers catch design mistakes before data issues happen. For example, a primary key should usually not be empty and should identify rows uniquely.
